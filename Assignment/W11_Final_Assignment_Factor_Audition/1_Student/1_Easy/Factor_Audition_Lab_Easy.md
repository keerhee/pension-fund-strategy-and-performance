# 팩터 오디션 실습과제 (Easy version)

2026-11-03 · 이기홍

## 한눈에 보기

기금의 팩터 슬리브에 어떤 팩터를 넣을지 Claude Code가 판정하고, 여러분은 그 결과를 확인하고 결재한다. 코드는 한 줄도 쓰지 않는다. 지시문 5개를 차례로 붙여넣으면 끝난다.

| 항목 | 내용 |
| --- | --- |
| 쓰는 데이터 | QDL 팩터 수익률 CSV만 쓴다 (종목 특성 parquet는 필요 없다) |
| 판정 방법 | 단순 t값 기준과 JKP(2023) 계층 베이지안 기준을 비교한다 |
| 결과물 | 판정표, 그림 3장, IC 안건서 1장, 판단 문제 답 |

수강생이 하는 일은 네 가지다.

1. 지시문을 Claude Code 데스크톱 앱(Code 탭) 입력 창에 붙여넣는다.
2. Claude Code가 보여 준 숫자와 그림이 그럴듯한지 확인한다.
3. 이상하면 "왜 이렇게 나왔는지 설명하고 고쳐 줘"라고 다시 시킨다.
4. 판단 문제에 답하고 안건서를 결재한다.

원본 과제(7단계)보다 단계를 줄였다. 오디션 시점은 2010년 한 번, 드로다운 테스트는 Value 겨울 한 구간만 본다.

## 무엇을 하는가 — 153명 오디션

153개 팩터 전부를 후보로 놓고 시작한다. 군집 13개는 뽑는 대상이 아니라, 각 팩터의 성적을 더 정확하게 읽는 데 쓰는 정보다.

현실 상황은 이렇다. 연기금이 해외주식 가운데 10조 원을 팩터 전략에 맡기려 한다. 학계와 운용사는 "이 팩터가 돈을 번다"며 수백 개를 내밀지만 기금은 최대 10개만 담을 수 있다. 과거 성적이 좋았던 팩터 중 상당수는 운이었으므로, 진짜 실력파만 골라내야 한다.

| 오디션 순서 | 비유 | 실습에서 하는 일 |
| --- | --- | --- |
| 1. 모두 시험을 본다 | 지원자 153명이 시험을 본다 | 153개 팩터의 과거 성적(단순 t값)을 구한다 |
| 2. 운을 걸러 낸다 | 실력이 없어도 7~8명은 우연히 합격선을 넘는다 | 단순 t값만으로는 가짜가 섞인다는 것을 확인한다 |
| 3. 같은 학원 성적을 함께 본다 | 학원 친구들이 대부분 못 봤는데 혼자 고득점이면 점수를 깎는다 | 13개 군집 정보로 점수를 보정한다(사후 t값) |
| 4. 최대 10명을 뽑는다 | 한 학원에서는 2명까지만 뽑는다 | 비슷한 팩터에 쏠려 한꺼번에 무너지는 일을 막는다 |
| 5. 미래 성적으로 채점한다 | 2010년까지의 성적으로 뽑고 이후 10년 성적을 본다 | 원점수 팀과 보정 점수 팀의 오탐 비율을 비교한다 |

정리하면, 군집 13개 중에서 고르는 것이 아니다. 153개 중에서 고르되, 군집 정보로 점수를 보정하고 군집별 인원 상한을 둔다.

## 꼭 필요한 기본 지식 4가지

### 1. 팩터 슬리브(factor sleeve)

기금 안에서 팩터 전략에 따로 떼어 맡긴 자금이다. 예를 들어 해외주식 350조 원 가운데 10조 원을 가치, 모멘텀, 수익성 같은 팩터에 투자한다. 이 실습은 그 10조 원에 어떤 팩터를 담을지 정한다.

### 2. 팩터를 많이 검정하면 가짜가 섞인다

팩터 하나를 t ≥ 1.96 기준으로 검정하면 효과가 없어도 5% 확률로 통과한다. 153개를 검정하면 평균 7~8개가 우연히 통과한다. 그래서 단순 t값만 믿으면 가짜 팩터를 슬리브에 넣게 된다.

### 3. 비슷한 팩터의 성적을 함께 본다 (계층 베이지안)

JKP(2023)는 153개 팩터를 13개 군집으로 묶었다. 어떤 팩터의 알파가 크게 나와도, 같은 군집의 다른 팩터들이 부진하면 그 알파를 깎아서 본다. 이렇게 깎는 것을 수축(shrinkage)이라 한다.

$$\underbrace{\hat\alpha^{\text{post}}}_{\text{믿을 만한 알파}} = \underbrace{\kappa}_{\text{신뢰 비중}}\,\underbrace{\hat\alpha}_{\text{그 팩터의 알파}} + (1-\kappa)\,\underbrace{\bar\alpha_{\text{cluster}}}_{\text{군집 평균 알파}}, \qquad 0 \le \kappa \le 1$$

- 왼쪽은 믿을 만한 알파(사후 평균)다.
- 오른쪽 첫 항은 그 팩터 자체의 추정 알파, 둘째 항은 같은 군집 팩터들의 평균 알파다.
- κ는 신뢰 비중이다. 표본이 짧고 잡음이 클수록 κ가 작아져 군집 평균 쪽으로 더 많이 끌려간다.

판정은 사후 t값으로 한다. 사후 t값은 믿을 만한 알파를 그 불확실성(사후 표준편차)으로 나눈 값이다.

$$\underbrace{t^{\text{post}}}_{\text{사후 t값}} = \frac{\text{믿을 만한 알파}}{\text{사후 표준편차}} \ \ge\ 1.96 \ \Rightarrow\ \text{편입}$$

### 4. 드로다운(drawdown)

누적가치가 과거 최고점에서 얼마나 떨어졌는지를 나타낸다.

$$\underbrace{DD_t}_{\text{드로다운}} = \frac{\overbrace{V_t}^{\text{현재 누적가치}}}{\underbrace{\max_{s \le t} V_s}_{\text{과거 최고점}}} - 1$$

V_t는 지금의 누적가치, 분모는 그때까지의 최고점이다. 좋은 팩터도 몇 년씩 손실을 낸다. 2018~2020년 가치 팩터의 긴 손실을 Value 겨울이라 부른다.

## 5단계 실습

모든 단계는 같은 순서로 진행한다. 어디(입력 창) → 입력(지시문 붙여넣기) → 출력(Claude Code가 만든 결과) → 확인(여러분이 볼 것).

### 1단계 — 실습 폴더를 만들고 규칙을 잠근다

판정 규칙은 결과를 보기 전에 정하고, Claude Code가 고치지 못하게 잠근다.

- 어디: Claude Code 데스크톱 앱, 작업 폴더 work/KAIST-BAF634-2025
- 입력:

```text
저장소 루트에 factor_audition/ 폴더를 만들고 다음을 해 줘.
1. factor_audition/CLAUDE.md 에 아래 규칙을 적는다.
   - 데이터는 from qdl.facade import QDL 로 읽는다. 이번에는 data/factors/ 의 CSV만 쓴다.
   - rules.yaml 은 절대 수정하지 않는다.
   - 날짜 d의 결정에는 d까지의 데이터만 쓴다.
   - 결과 숫자는 반드시 실행해서 얻고, 짐작해서 쓰지 않는다.
2. factor_audition/rules.yaml 을 만든다.
   편입: 사후 t ≥ 1.96 / 퇴출: 사후 t < 1.00 / 슬리브 최대 10개 / 군집당 최대 2개
3. rules.yaml 을 고치려 하면 막는 Claude Code 훅을 .claude/settings.json 에 설정하고,
   실제로 막히는지 한 번 시험해 결과를 보여 줘.
4. 미국과 한국 팩터가 각각 몇 개이고 언제부터 있는지 표로 보여 줘.
```

- 출력: CLAUDE.md, rules.yaml, 훅 시험 결과("수정할 수 없다" 메시지), 데이터 요약표
- 확인: 훅 시험에서 rules.yaml 수정이 정말 막혔는가? 미국 팩터는 153개인가?

### 2단계 — 판정 엔진을 돌린다

153개 팩터를 13개 군집으로 묶고, 단순 t값과 사후 t값을 나란히 구한다.

- 어디: 같은 입력 창
- 입력:

```text
미국 전체 표본으로 다음을 해 줘. 결과는 factor_audition/results/ 에 저장한다.
1. 팩터 수익률의 상관으로 13개 군집을 만든다(Ward 방식).
   각 군집에는 all_themes 파일에서 가장 닮은 테마 이름을 붙인다.
2. 팩터마다 시장 대비 알파(CAPM)와 단순 t값을 구한다.
3. JKP(2023) 방식의 계층 베이지안 모형으로 사후 알파와 사후 t값을 구한다.
4. 단순 t ≥ 1.96, 단순 t ≥ 3, 사후 t ≥ 1.96 을 통과한 팩터 수를 표로 비교한다.
5. x축 단순 알파, y축 사후 알파인 그림을 군집별 색으로 그리고 45도선을 넣는다.
```

- 출력: 통과 팩터 수 비교표, 수축 그림(fig_shrinkage.png)
- 확인: 점들이 45도선보다 0 쪽으로 눕는가? 가장 많이 끌려 내려온 팩터는 어느 군집인가?

### 3단계 — 2010년으로 돌아가 오디션을 연다

2010년 말까지의 데이터만 보고 슬리브를 짠 뒤, 2011~2020년 실제 성과로 채점한다.

- 어디: 같은 입력 창
- 입력:

```text
2010년 12월까지의 데이터만으로 2단계를 다시 하고 슬리브를 두 개 만들어 줘.
- 슬리브 가: 단순 t값이 높은 순으로 rules.yaml 제약 안에서 채운다.
- 슬리브 다: 사후 t값이 높은 순으로 rules.yaml 제약 안에서 채운다.
그다음 2011년 1월부터 2020년 12월까지 두 슬리브의 성과를 비교해 줘.
- 연 수익률, 변동성, 샤프 비율
- 편입한 팩터 가운데 이후 10년 알파가 음수였던 팩터 비율(오탐 비율)
- 두 슬리브의 누적수익률 그림(fig_audition.png)
2011년 이후 데이터를 2010년 결정에 쓰지 않았는지 마지막에 점검해 알려 줘.
```

- 출력: 두 슬리브 명단, 성과 비교표, 누적수익률 그림
- 확인: 오탐 비율은 어느 슬리브가 낮은가? Claude Code가 미래 데이터를 쓰지 않았다고 확인했는가?

### 4단계 — Value 겨울을 버티는 규칙을 시험한다

가치 팩터 be_me가 2017~2021년에 겪은 손실에 미리 정한 대응 규칙을 적용해 본다.

| 드로다운 | 하는 일 |
| --- | --- |
| −20% 이하 | 그 시점 데이터로 다시 검정해 알파가 양수일 확률을 보고한다 |
| −30% 이하 | 그 확률이 0.90 이상이면 유지하고, 미만이면 비중을 절반으로 줄인다 |
| −10% 위로 회복 | 줄인 비중을 원래대로 되돌린다 |

- 어디: 같은 입력 창
- 입력:

```text
가치 팩터 be_me 의 2017년 1월~2021년 12월 월 수익률에 위 표의 대응 규칙을 적용해 줘.
알파가 양수일 확률은 매번 그 시점까지의 데이터로 2단계 모형을 다시 돌려 구한다.
그대로 보유한 경우와 누적수익률, 최대 드로다운을 표와 그림(fig_ladder.png)으로 비교해 줘.
규칙이 작동한 달마다 무엇을 했고 왜 했는지 한 문장씩 기록해 줘.
```

- 출력: 정책 비교표, 드로다운 그림, 행동 기록
- 확인: 손실이 깊어지는 동안 알파가 양수일 확률은 얼마나 움직였는가?

### 5단계 — IC 안건서를 받아 결재한다

### 판단 문제 (셋 중 둘을 골라 답한다)

1. 운용역이 "요즘 가치 팩터가 유리하니 편입 기준을 1.5로 낮추자"고 한다. 규칙을 잠가 둔 이유를 들어 답한다.
2. 표본이 짧은 새 팩터가 단순 t값은 2.4인데 사후 t값은 1.7이다. 왜 떨어졌는지, 편입해도 되는지 답한다.
3. Value 겨울의 −30% 구간에서 알파가 양수일 확률이 0.93인데 한 위원이 축소를 요구한다. 규칙을 지킬 때와 예외를 둘 때 기금이 각각 무엇을 잃는지 답한다.
