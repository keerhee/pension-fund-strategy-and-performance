# 독립세션 XS — 자율주행 포트폴리오

Andrew Ang·Nazym Azimbayev·Andrey Kim, *The Self Driving Portfolio: Agentic
Architecture for Institutional Asset Management* (arXiv 2604.02279, 2026-04-02,
31쪽·전시 11개)를 **우리 16주 교재로 구현하는** 세션이다.

## 1. 이 세션이 필요한 이유

논문의 주장은 한 문장이다 — **"에이전틱 AI는 투자자의 역할을 분석 실행에서
감독으로 옮긴다."** 약 50개 전문 에이전트가 CMA를 만들고, 20가지 넘는 방법으로
포트폴리오를 짜고, 서로의 결과를 비평하고 투표한다. 리서처 에이전트는 아직 없는
방법을 제안하고, 메타 에이전트는 과거 예측을 실현 수익률과 대조해 **에이전트의
코드와 프롬프트를 스스로 고쳐 쓴다.** 그리고 이 전체를 **투자정책서(IPS)가
통제한다** — 사람 운용역을 규율하던 바로 그 문서다.

우리 과정은 이미 이 파이프라인의 부품을 전부 가르쳤다. 빠진 것은 **부품을 자율
시스템으로 엮는 방법**뿐이다. 이 세션이 그것을 채운다.

## 2. 논문 구조 ↔ 우리 교재

논문의 각 층이 우리 주차와 정확히 대응한다. 이 표가 세션의 뼈대다.

| 논문의 층 | 하는 일 | 우리 교재 |
|---|---|---|
| 거버넌스 | IPS가 전 과정을 제약 | W01 자산소유자 · **W16 TPA** |
| 입력 | 자본시장 가정(CMA) 생성 | **W03 연기금 모델과 CMA** |
| 구성 | 20+ 방법이 경쟁 | **W04 MVO** · **W05 BL** · **W06 리스크패리티·HRP** |
| 비평·투표 | 서로의 안을 심사·표결 | **16주 내내의 IC(모의 투자위원회)** |
| 탐색 | 리서처가 새 방법 제안 | W13 팩터투자 · W14 매크로·CTA |
| 자기개선 | 메타 에이전트가 코드·프롬프트 재작성 | **W10 위험관리와 성과평가** |

**가장 중요한 연결**: 학생이 16주 동안 사람으로서 해온 **IC의 심사·표결이 논문의
비평·투표 층**이다. 새로운 것을 배우는 세션이 아니라, **해온 일을 자동화하는**
세션이라는 점을 처음부터 못박는다.

## 3. harness로 구조를 세운다

구조 설명은 `revfactory/harness`(황민호, Apache-2.0, ★8.8k)를 쓴다. Claude Code용
**메타 스킬** — "도메인에 맞는 에이전트 팀을 설계하고, 각 에이전트의 역할을 정의하고,
그들이 쓸 스킬을 생성한다."

harness를 고른 이유는 논문 구조와 **개념이 1:1로 맞기 때문**이다.

| 논문 | harness |
|---|---|
| IPS가 파이프라인을 통제 | Phase 5-4 — `CLAUDE.md`에 하네스 포인터·트리거 규칙 등록 |
| 50개 전문 에이전트 | Phase 2-3 에이전트 분리 기준 → Phase 3 `.claude/agents/{name}.md` |
| CMA 병렬 생성 | Phase 2-2 **팬아웃/팬인** 패턴 |
| 20+ 방법 경쟁 | Phase 2-2 **전문가 풀** 패턴 |
| 비평·투표 | Phase 2-2 **생성-검증** 패턴 |
| 리서처의 새 방법 제안 | Phase 7-4 진화 트리거 |
| 메타 에이전트의 자기 재작성 | **Phase 7 하네스 진화** (7-1 피드백 → 7-2 반영 → 7-3 이력) |

harness의 첫 번째 원칙이 "**하네스는 고정물이 아니라 진화하는 시스템이다**"인데,
이것이 곧 논문의 메타 에이전트다. 우연이 아니라 같은 문제를 같은 방향으로 푼 것이고,
학생에게 이 점을 보이는 것 자체가 교육적이다.

## 4. MVP — 50개를 7개로 줄인다

50 에이전트를 그대로 만들지 않는다. **파이프라인의 여섯 층을 모두 지나되 각 층을
최소로** 두어, 한 세션(60~90분) 안에 끝까지 돌려본다.

| # | 에이전트 | 층 | 교재 |
|---|---|---|---|
| 0 | `ips-guardian` | 거버넌스 | W01 · W16 |
| 1 | `cma-builder` | 입력 | W03 |
| 2 | `alloc-mvo` | 구성 | W04 |
| 3 | `alloc-bl` | 구성 | W05 |
| 4 | `alloc-riskparity` | 구성 | W06 |
| 5 | `ic-critic` | 비평·투표 | IC 전체 |
| 6 | `meta-reviewer` | 자기개선 | W10 |

**데이터는 새로 만들지 않는다.** 이미 각 주차 폴더에 있는 실습 CSV와 실습데이터 덱의
수집 프롬프트를 그대로 쓴다. 앞 주차 산출물을 뒤 주차가 재사용하는 사슬
(W02 패널 → W04 공분산 → W05 BL → W06 ERC/HRP → W10 성과평가 → W16 TPA)이
그대로 이 파이프라인의 데이터 흐름이 된다.

## 5. 실습 서술 방식 — [어디] [입력] [출력] [확인]

입문자 기준이다. 코딩 경험이 없어도 따라올 수 있도록 **네 칸을 고정 형식으로** 쓴다.

```
[어디]  터미널 · 폴더 W16_TPA/self-driving-mvp/
[입력]  harness로 자율주행 포트폴리오 에이전트 팀을 구성해줘.
        IPS는 ips.md에 있다.
[출력]  .claude/agents/ 에 7개 .md 파일
        .claude/skills/ 에 오케스트레이터 1개
        CLAUDE.md 에 하네스 포인터 추가됨
[확인]  ls .claude/agents 하면 7줄이 나온다.
        하나를 열어 "## 팀 통신 프로토콜" 항목이 있으면 정상이다.
```

**[확인]을 반드시 넣는다.** 입문자가 막히는 지점은 명령이 아니라 "이게 맞게 된
건지 모르겠다"이다. 매 단계에 눈으로 확인할 수 있는 기준을 준다.

## 8. 확인이 필요한 것

1. **자리** — W16 안의 XS로 둘지, 독립 폴더(`XS_자율주행포트폴리오/`)로 뺄지.
   이 세션은 도구·구현 비중이 커서 성격이 다른 면이 있다.
2. **IC 케이스 덱** — 다른 특별세션은 전부 강의본 + IC 케이스 짝이다. XS도
   케이스를 붙일지(예: "우리 기금은 자율 파이프라인을 도입할 것인가 —
   감독 범위와 킬스위치를 의결하라"), 강의본만 만들지.
3. **실습 실증 수준** — MVP를 **실제로 돌려 출력을 캡처해 덱에 넣을지**, 예상 출력을
   서술로만 둘지. 실제 실행을 권한다. [확인] 칸의 신뢰도가 달라진다.
4. **분량** — 34장이 적정한지. 실습 파트를 늘리면 40장을 넘길 수 있다.
