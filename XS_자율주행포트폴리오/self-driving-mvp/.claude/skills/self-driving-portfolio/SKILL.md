# self-driving-portfolio — 오케스트레이터

7개 에이전트를 한 사이클로 엮는다. 개별 스킬이 "각자 무엇을 어떻게 하는가"라면,
이 문서는 **누가 언제 어떤 순서로 협업하는가**를 정한다.

## 사용자는 명령어를 치지 않는다

이 실습의 원칙이다. 폴더 생성·가상환경·패키지 설치·데이터 수집을 사용자에게 시키지
않는다. 필요하면 직접 처리하고 **결과만 보고한다.** 사용자가 하는 일은 프롬프트를
쓰고 결과를 읽고 무엇을 승인할지 판단하는 것뿐이다.

## 실행 순서

| 단계 | 에이전트 | 스킬 | 패턴 | 산출 |
|---|---|---|---|---|
| 0 | `ips-guardian` | `ips-check` | — | (다른 단계가 호출) |
| 1 | `cma-builder` | `cma-build` | 파이프라인 | `cma.json` |
| 2 | `alloc-mvo` · `alloc-bl` · `alloc-riskparity` | `portfolio-construct` | **팬아웃** | `alloc_*.json` |
| 3 | `ic-critic` | `ic-vote` | **팬인** + 생성-검증 | `ic_vote.json` |
| 4 | `meta-reviewer` | `meta-review` | 파이프라인 | `meta_review.json` |

사용자가 "한 사이클 돌려줘"라고 하면 1→4를 순서대로 수행한다.
개별 에이전트를 이름으로 부르면 그 단계만 수행한다.

## 데이터 전달 프로토콜

에이전트끼리 값을 직접 넘기지 않는다. **모두 `runs/{YYYY-MM-DD}/`의 JSON을 거친다.**
이유는 감사 가능성이다 — 어느 단계의 무엇이 다음에 들어갔는지 파일로 남는다.
IPS 7.2항(근거를 남기지 않은 안은 무효)이 이 설계를 요구한다.

## 에러 핸들링

| 상황 | 처리 |
|---|---|
| 배분 에이전트 1개 실패 | 나머지로 표결하고 실패 사실을 `ic_vote.json`에 남긴다 |
| 배분 에이전트 전부 실패 | 사이클을 중단한다. 직전 사이클 결과를 재사용하지 않는다 |
| 모든 후보가 IPS 위반 | `winner: null`로 두고 사람에게 escalate |
| CMA 예측오차가 과대 | 중단하지 않는다. `meta-reviewer`가 다음 사이클 제안으로 남긴다 |

## 정책을 바꿔 다시 돌릴 때

사용자가 "하한을 3.5로 낮추고 다시 돌려줘"처럼 요청하면 **`ips.md`만 고친다.**
코드나 에이전트 정의는 건드리지 않는다. 새 결과는 `runs/{날짜}-b/`처럼 별도 폴더에
두고, 앞 결과와 나란히 비교해 보고한다. 이것이 거버넌스 층이 작동하는 모습이다.

## 사람의 개입 지점

1. **집행 승인** — 산출은 권고안이다(IPS 7.1항).
2. **지시문 개정** — `meta-reviewer`의 제안은 사람이 검토한 뒤에만 반영한다(7.4항).
3. **정책 변경** — `ips.md` 수정은 사용자가 명시적으로 요청할 때만 한다.
