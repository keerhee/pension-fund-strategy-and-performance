# XS 팀 프로젝트 · 2단계
## 최종 제품 — 자율주행 자산운용 회사(Self-Driving Asset Management Company)를 제출한다

> **한 줄 문제.** 1단계의 설계도를 **실제로 도는 회사**로 완성한다. 에이전트가 평가 구간의 매 분기를 스스로 운용하고, 사람은 CIO로서 결정하며, 돌발 상황이 오면 **코드를 고치지 않고 입력만 바꿔** 대응하는 회사다.
>
> **언제.** 기말고사 주(W16) — 발표 20분(라이브 시연 7분 포함) + 질의 10분. 교수와 청중은 이 회사에 기금을 맡길지 정하는 **기금운용위원회**다.
>
> **무엇을.** 제품 저장소(**MVP v1**) + 회사 문서 3종 + 최종 보고서 + 발표 덱 + 시연 영상 + 기여표(§5). 100점(§8).

1단계 가이드의 용어와 역할(A~F)을 그대로 쓴다. 필수 기능 하나하나의 상세 명세(식 · 검산 예제 · [확인] 기준)는 **상세 명세서**(`XS_Team_Project_Guide.pdf`) §5에 있다.

## 1. 회사란 무엇인가 — 부서 지도

자율주행 자산운용 회사는 **제품(시스템) + 운영 규정 + 사람의 감독**이다. 부서마다 에이전트와 장치가 일하고, 팀의 역할이 그 부서를 책임진다.

| 부서 | 하는 일 | 일하는 에이전트 · 장치 | 책임 역할 | 필수 기능 |
|---|---|---|---|---|
| 이사회 · 준법 | IPS로 전 과정을 제약하고, 규칙을 바꾸는 절차를 지킨다 | `ips-guardian`, 자동 기각, 킬스위치, 감사 기록, 변경 이력 | A | M1 · M2 |
| 리서치 | 국면을 판정하고 자본시장 가정(CMA)을 만들고 새 연구를 읽는다 | `macro-agent`, `cma-builder`, `research-agent` | B | M3 · M4 · M5 |
| 운용 | 서로 다른 배분안을 경쟁시킨다 | PC 에이전트 4개 이상 (적대적 분산자 포함) | C | M6 |
| 리스크 · 투자위원회 | 위험을 같은 양식으로 보고하고, 서로 검토하고, 표결하고, IC 보고서를 쓴다 | `cro-agent`, 상호 검토, 투표, `ic-agent` | D | M7 · M8 · M9 |
| **CIO 사무실 (사람)** | IC 보고서를 받고 승인 · 조건부 승인 · 반려를 결정한다 | 시연 화면의 사람 CIO 결정 · `cio_decisions.csv` | CIO 겸임자 | M9 |
| 사후 학습 | 예측과 실현을 대조하고 개선을 제안한다 — 반영은 사람 승인 뒤에만 | `meta-reviewer`, 변경 제안 → 승인 → 테스트 → 승격·롤백 | D | M10 |
| 운영 · 플랫폼 | 회사를 매 분기 돌리고, 입력을 받고, 누가 돌려도 같은 숫자를 낸다 | 오케스트레이터, **시연 화면**, **접수 창구(접수 에이전트)**, 채점 콘솔, 재실행 점검 | E | S1 · S2 · S4 |
| 대외 · 기획 | 고객에게 보고하고 회사를 소개하고, 우리 회사만의 새로운 점을 만든다 | 고객 보고서, 회사 문서, 창의 트랙 | F (5명 팀은 전원) | S3 |

## 3. 필수 기능 — 회사가 반드시 해야 하는 일

### 3.1 운용 시스템 — M1~M10

예시 MVP가 갖춘 열 가지를 **우리 회사의 IPS와 구성으로** 갖춘다. 상세 명세는 상세 명세서 §5.

| # | 기능 | 한 줄 확인 기준 |
|---|---|---|
| M1 | IPS와 자동 기각 | 한 종목 50% 같은 위반 안을 넣으면 사유와 함께 기각되고 표결에 오르지 않는다 |
| M2 | 하네스 — 감사 기록과 킬스위치 | 에이전트가 IPS · 스킬 · 코드를 직접 고치지 못하고, 제안서만 남긴다 |
| M3 | 매크로 에이전트 | 같은 `as_of`로 다시 돌리면 국면 라벨이 같다 |
| M4 | CMA 에이전트 | 수축 평균과 Ledoit–Wolf 공분산, 추정 구간이 기록된다 |
| M5 | 리서치 에이전트 | as_of 이전 자료만 읽고, 변경 제안이 최소 1건 나와 처리된다 |
| M6 | PC 에이전트 4개 이상 | 계열이 다른 안 셋 이상 + 적대적 분산자, 안들 사이 추적오차 보고 |
| M7 | CRO 에이전트 | 모든 안이 같은 양식의 위험 보고서(변동성 · CVaR · 위험기여 · 스트레스)를 받는다 |
| M8 | 상호 검토와 수정 보르다 투표 | 검산 예제를 코드로 재현하고, 분기마다 투표자별 순위와 최하위 지목이 남는다 |
| M9 | IC 보고서와 CIO 결정 | 모든 분기에 `ic_report.md`와 `cio_decision.md`가 있다 |
| M10 | 메타 리뷰와 학습 루프 | 변경 제안 → 승인 → 테스트 → 승격 또는 롤백이 최소 1회 기록된다 |

### 3.2 회사 운영 — S1~S4 (2단계에서 새로 요구)

| # | 기능 | 무엇을 | 확인 기준 |
|---|---|---|---|
| **S1** | **시연 화면이 회사의 창구** | `start.command` · `start.bat`을 누르면 시연 화면이 먼저 열린다 — 단계 진행 · 근거 파일 · 사람 CIO 승인 · 1쪽 보고서 · 두 실행 비교. 채점 콘솔은 그 안에서 연다 | 위원회 앞에서 한 분기를 처음부터 CIO 결정까지 시연할 수 있다. 예시의 `demo/시연화면_예시MVP.html`을 그대로 써도 된다 |
| **S2** | **접수 창구 — 입력 형식이 자유롭다** | 입력 파일과 돌발 과제를 **표준 형식 md**로도, **메모 · 메일 같은 자유 형식**으로도 받는다. 자유 형식은 접수 에이전트가 표준 형식으로 옮겨 근거 원문과 함께 보여 주고, **사람이 확인해야** 입력이 된다 | 교수가 메모로 준 돌발 과제를 시연 화면에 그대로 올려 대응한다. 해석 기록이 입력 검사에 남는다 |
| **S3** | **고객 보고** | 분기마다 고객에게 보내는 보고서 — 무엇을 왜 바꿨는지, 위험은 어떤지, 사람이 무엇을 결정했는지 | 고객 분기 보고서 샘플 1부 (§4) |
| **S4** | **돌발 대응 — 입력만 바꾼다** | IPS 변경 · 시장 충격 · 모델 교체가 오면 코드를 고치지 않고 입력만 바꿔 다시 돌린다 | 라이브 점검 L1~L3 대응 (§6.2) |

**입력 형식 — 두 가지 다 된다.** 표준 형식은 정해진 줄(`기준 분기:` · `유형:` · `- 항목: 값`)이고, 자유 형식은 메모 · 메일 · 문장(`.md` · `.txt`)이다. 어느 형식이든 엔진이 읽는 항목은 같다 — IPS 한도, 시장 충격(주식 · 금리 · 금 · 원자재), 모델 교체. 쓰는 법과 예시 6개는 `3_Example_MVP/올릴파일/README.md`. 접수 에이전트를 LLM으로 바꾸고 그 해석을 검증하는 것은 좋은 창의 트랙이다.

**원칙은 셋이다 — 계산은 코드, 판단은 에이전트, 결정은 사람.** 기대수익률 · 공분산 · 최적화 · 점수 집계는 반드시 코드가 한다. LLM에게 숫자 계산을 맡기면 계산 재현 점검(T6)에서 떨어진다.

## 4. 회사 문서 3종

제품만으로는 회사가 아니다. 위원회가 "이 회사에 기금을 맡겨도 되는가"를 판단할 문서를 낸다.

| 문서 | 분량 | 담을 것 | 주로 쓰는 역할 |
|---|---|---|---|
| **① 회사 소개서** (`company/company_profile.md`) | 2쪽 | 회사 이름 · 고객 기금 · 운용 목적 · 회사가 고객에게 주는 것 · 부서 지도(§1) · 사람이 맡는 일 · **이 회사가 하지 않는 일과 한계** | F |
| **② 운용 규정집** (`company/operating_rules.md`) | 3~5쪽 | IPS 요약 · 자동 기각 규칙 · 킬스위치 · 변경 관리(제안 → 승인 → 테스트 → 승격·롤백) · **사고 대응 절차**(돌발 입력 · 시스템 오류 · 데이터 지연) · 사람 승인 지점 목록 | A |
| **③ 고객 분기 보고서 샘플** (`company/client_report_YYYY-MM.md`) | 2쪽 | 한 분기를 골라 — 국면 판단 · 배분 변화와 이유 · 위험 지표 · 기각된 안과 사유 · 사람 CIO의 결정과 사유 · 다음 분기 점검 사항 | D · F |

여기에 **도입 의결문**(`reports/resolution.md`)을 더한다 — 기금운용위원회의 입장에서 "이 회사에 기금을 맡길 것인가"를 승인 · 조건부 승인 · 부결 중 하나로 쓰고, 조건부라면 감독 범위 · 킬스위치 · 사람 승인 지점을 명시한다(CIO 겸임자가 초안).

## 5. 제출물

**제품 저장소(MVP v1)** — 예시 MVP와 같은 모양에 회사 문서를 더한다.

```
team-XX.zip
  README.md              실행 방법 + "예시 MVP와 달라진 점" 표 + 1단계 피드백 반영표
  start.command          맥 — 더블클릭하면 시연 화면이 열린다 (채점 콘솔은 그 안에서)
  start.bat              윈도 — 같은 기능
  dashboard.html         정적 보기 (파이썬 없이 읽기 전용)
  requirements.txt
  ips.md                 최종 IPS (보호 파일) + 변경 이력
  PREREG.md              사전 등록표 (1단계에서 낸 것 + 변경 이력)
  CHANGELOG.md           변경 제안 → 승인·반려 → 테스트 → 승격·롤백
  INTERVENTIONS.md       CIO 결정 · 개입 기록
  CLAUDE.md              Claude Code 라이브 모드 규칙
  .claude/agents/  .claude/skills/  config/
  data/                  DATA.md · 데이터 · research_corpus.csv · cio_decisions.csv · approvals.csv
  sdp/ (또는 팀 패키지)  계산 코드 · 하네스 · 오케스트레이터 · 점검 · 콘솔 · 접수 에이전트
  console/               index.html 채점 콘솔
  demo/                  시연화면_예시MVP.html 시연 화면(첫 화면) · standalone/ 단독판
  올릴파일/              팀이 시연에 쓰는 입력 · 돌발 예시 (표준 형식 · 자유 형식)
  runs/{YYYY-MM}/        분기별 실행 증거 — 숫자 json · 판단 md · trace.jsonl
  runs_rerun/{1,2,3}/    LLM 판단 부분 재실행 3회
  reports/               performance.md · selfcheck.md · resolution.md(도입 의결문)
  company/               회사 소개서 · 운용 규정집 · 고객 분기 보고서 샘플 (§4)
  deck/                  발표 덱
  CONTRIB.md             팀원별 역할 · 만든 파일 · 커밋 범위
```

그리고 따로 낸다 — **최종 보고서**(PDF, 15쪽 이내), **시연 영상**(5분 이내 — 시연 화면에서 한 분기와 돌발 하나), **발표 덱**.

API 키 · 개인 인증 정보는 넣지 않는다. 실제 매매나 외부 발송 기능은 만들지 않는다 — 이 회사는 **분석 전용**이다.

**최종 보고서의 장 구성 (권장)**

1. 1단계 피드백 반영표
2. 회사와 고객 — IPS 숫자마다 근거
3. 시스템 — 예시 MVP와 달라진 점, 창의 기능
4. 결과 — 채택 경로 대 각 배분안 계속 보유 · 60/40 · 동일가중 (연율 수익 · 변동성 · 샤프 · 최대낙폭 · 회전율)
5. 감독 — 자동 기각 · 킬스위치 · CIO 개입이 무엇을 막고 무엇을 놓쳤는가, 기각안의 사후 성과
6. 재현성 — 재실행 3회의 일치도
7. 정책 실험 — IPS 조항 하나를 바꿨을 때
8. 도입 의결과 한계

## 6. 채점 — 채점자가 회사를 직접 돌린다

### 6.1 채점자의 실행 순서

채점자는 **파이썬 3.10 이상과 브라우저**만 쓴다.

1. zip을 풀고 `start.command`(맥) · `start.bat`(윈도)를 더블클릭한다 → **시연 화면**이 열린다.
2. 시연 화면에서 아무 분기나 ▶ 라이브 실행 → 사람 CIO 결정 → 1쪽 보고서까지 돌린다.
3. 오른쪽 위 「채점 콘솔 (보조) →」 → **공개 점검 T1~T8 전체 실행**, 분기 다시 계산, 문서 읽기.

코드가 계산한 숫자는 제출본과 소수 6자리까지 같아야 한다. LLM의 판단 부분은 녹화본을 재생하므로 양식과 근거 기록만 본다. 시연 화면이 뜨지 않으면 실행 점수(T1)는 0점이다.

### 6.2 라이브 점검 L1~L3 — 발표 당일, 회사의 돌발 대응

미리 알려 주지 않는다. 교수는 과제를 **md 파일 또는 메모 · 메일 같은 글**로 준다. 팀은 시연 화면에 그대로 올려 7분 안에 대응한다.

| # | 교수가 주는 것 (예) | 회사가 보여야 할 것 |
|---|---|---|
| L1 | IPS 조항 변경 — 「변동성 한도를 7%로 줄이자」 | 입력 파일로 올려 한 분기를 다시 돌리고, 채택안이 어떻게 바뀌었는지 설명 |
| L2 | 시장 충격 — 「다음 달 증시 15% 급락, 금리 1.5%p 상승」 | 돌발 과제로 올려 새 분기를 진행하고, IC 보고서를 받아 CIO가 그 자리에서 결정 |
| L3 | 숨은 결함 — 비중 합 1.03인 안, 결정 시점 뒤의 사건이 섞인 메모 | 회사가 잡아내는가, 못 잡으면 어디서 놓쳤는지 감사 기록으로 찾아내는가 |

자유 형식으로 받은 과제는 접수 에이전트의 해석을 **위원회 앞에서 확인하고** 투입한다 — 해석이 틀렸다면 그것을 잡아내는 것도 감독 점수다.

| 발표 · 문서 | 10 | 위원회가 10분 안에 이해하고 결정할 수 있다. 회사 문서 3종과 의결문이 일관된다 | 숫자는 많은데 결론이 없다 |

**감점.** MVP v0 미제출(1단계) −5 · 평가 구간 정보를 결정에 쓴 경우(미래정보) −10 · 사전 등록값을 기록 없이 바꾼 경우 −5 · 불리한 결과를 보고서에서 뺀 경우 −5.

**개인 점수 = 팀 점수 × 개인 계수(0.8~1.1).** 계수는 `CONTRIB.md` · 저장소 커밋 기록 · 동료 평가(팀원끼리 익명, 5점 척도)로 정한다. 기본값은 1.0이고, 맡은 부서의 필수 기능이 동작하지 않으면 그 담당자의 계수가 내려간다. 5명 팀에서 F를 나눠 맡은 몫은 `CONTRIB.md`에 각자 적는다.
