# XS 팀 프로젝트 · 1단계
## 프로포절 — 우리 회사의 자율운용 설계도를 내고, 첫 분기를 돌려 보인다

> **한 줄 문제.** 우리 팀은 한 기금의 돈을 맡아 운용하는 **자율주행 자산운용 회사**를 세운다. 1단계에서는 그 회사의 고객(기금)과 투자정책서(IPS), 시스템 설계도, 데이터 계획, 사전 등록표를 내고, 예시 MVP를 우리 IPS로 바꿔 **첫 분기를 처음부터 끝까지 한 번 돌려 보인다.**
>
> **언제.** 중간고사 다음 주(W09) 수업 시간 — 발표 10분 + 질의 5분.
>
> **무엇을.** 제출물 6종(§4). 1단계는 점수를 매기지 않고 피드백을 준다. 다만 **MVP v0가 없으면 최종 점수에서 5점을 뺀다.**

## 0. 두 단계 한눈에 보기

| | 1단계 — 프로포절 (이 문서) | 2단계 — 최종 제품 |
|---|---|---|
| 언제 | W09 중간고사 다음 주 | W16 기말고사 주 |
| 무엇을 보이나 | 설계도와 첫 분기 한 번 | 평가 구간 전체를 스스로 운용하는 회사 |
| 제품 | **MVP v0** — 예시 MVP + 우리 IPS, 첫 분기 완주 | **MVP v1** — 우리 회사의 자율운용 시스템 전체 |
| 발표 | 10분 + 질의 5분 | 20분(라이브 시연 7분 포함) + 질의 10분 |
| 평가 | 점수 없음 · 피드백 · v0 미제출 −5 | 100점 (2단계 가이드 §8) |

두 단계는 하나의 저장소로 이어진다. 1단계에서 낸 IPS·사전 등록값은 2단계에서 그대로 쓰고, 바꾸면 사유를 `CHANGELOG.md`에 남긴다.

**용어.** 이 문서에서 처음 나오는 말을 먼저 정리한다.

| 용어 | 뜻 |
|---|---|
| IPS (투자정책서) | 기금의 목적·목표 수익률·위험 한도·자산군 범위를 적은 문서. 시스템의 모든 판단을 제약한다 |
| 에이전트 | 목표를 받으면 스스로 단계를 정하고 도구를 불러 일을 끝내는 AI 작업자. 운용 현장의 애널리스트·PM·리스크 담당자 한 사람의 역할 |
| 하네스 | 에이전트에게 지시·도구·가드레일을 연결하고 실행 기록을 남기는 바깥 틀 — 자동 기각, 킬스위치, 감사 기록 |
| CIO | 최고투자책임자. 이 회사에 남는 유일한 사람의 결정자 — IC 보고서를 받고 승인·조건부 승인·반려를 결정한다 |
| 예시 MVP | 교수가 배포한 출발점 시스템(`3_Example_MVP/`). 가상 기금 KFP, ETF 11개, 에이전트 13개, 분기 12회 결정 |
| 시연 화면 | 예시 MVP를 `start.command`로 열면 나오는 첫 화면 — 단계 진행 · 근거 파일 · 사람 CIO 승인 · 1쪽 보고서 |

## 1. 최종 목표 미리 보기 — 자율주행 자산운용 회사

2단계에서 완성할 회사는 이런 모습이다.

```
고객 기금 ── IPS ──▶ [리서치] 매크로 · CMA · 리서치 메모
                         ▼
                    [운용] 배분안 4개 이상 경쟁 (적대적 분산자 포함)
                         ▼
                    [리스크 · 투자위원회] IPS 자동 심사 → 위험 보고 → 상호 검토 · 투표 → IC 보고서
                         ▼
                    [CIO 사무실 — 사람] 승인 · 조건부 승인 · 반려
                         ▼
                    [사후 학습] 예측 대 실현 → 개선 제안 → 사람 승인 뒤에만 반영
```

에이전트가 분기마다 이 흐름을 스스로 돌리고, 사람은 CIO로서 결정만 한다. 돌발 상황(IPS 변경 · 시장 충격 · 모델 교체)이 오면 **코드를 고치지 않고 입력만 바꿔** 대응한다. 1단계는 이 회사의 **설계도와 첫 분기 시운전**이다.

## 2. 팀 — 이미 구성된 5~6명

팀은 이미 짜여 있다. 아래 여섯 역할을 나눠 맡는다. 역할 A~D는 회사의 핵심 부서이고, E는 회사를 실제로 돌리는 운영 플랫폼, F는 회사의 대외 얼굴과 창의를 맡는다.

| 역할 | 회사에서는 | 만드는 것 (최소) | 책임지는 질문 |
|---|---|---|---|
| **A. 거버넌스·하네스** | 이사회 · 준법 | `ips-guardian`, 자동 기각 · 킬스위치 · 감사 기록 · 변경 이력 | 이 회사가 IPS를 어기는 일이 원천적으로 불가능한가? |
| **B. 리서치·입력** | 리서치 부서 | `macro-agent`, `cma-builder`, `research-agent`, 데이터 | 시장과 새 연구가 어떤 경로로 결정에 들어오는가? |
| **C. 포트폴리오 구성** | 운용 부서 | PC 에이전트 4개 이상 (적대적 분산자 포함) | 서로 충분히 다른 안이 경쟁하는가? |
| **D. 심의·학습** | 리스크 · 투자위원회 | `cro-agent`, 상호 검토, 투표, `ic-agent`, `meta-reviewer` | 표결이 합의와 반대를 함께 드러내는가? 학습이 규율을 무너뜨리지 않는가? |
| **E. 운영 플랫폼·재현성** | 운영 · IT | 오케스트레이터, 시연 화면, 채점 콘솔, 접수 창구, 재실행 점검 | 누가 돌려도 같은 숫자가 나오는가? 돌발 입력이 화면 하나로 들어가는가? |
| **F. 대외·창의** | 고객 · 기획 | 회사 소개서, 고객 보고서, 창의 트랙, 발표 총괄 | 우리 회사만의 새로운 점은 무엇이고, 고객은 무엇을 받는가? |

**인원에 따른 배치**

| 팀 인원 | 배치 |
|---|---|
| **6명** | A~F를 한 명씩 맡는다. |
| **5명** | A~E를 한 명씩 맡고, **F는 팀 전원이 나눠 맡는다** — 회사 소개서는 A, 고객 보고서는 D, 창의 트랙과 발표 총괄은 E가 이끈다(팀이 바꿔도 된다). |

**CIO는 팀원 한 명이 겸한다 — A는 겸하지 않는다.** 규칙을 만든 사람이 그 규칙의 예외를 승인하게 되기 때문이다. 6명 팀은 F가, 5명 팀은 B·C 중 한 명이 겸하는 것을 권한다.

**1단계에서 역할별로 낼 것**

| 역할 | 1단계 산출물 |
|---|---|
| A | `ips.md` 초안과 숫자마다 근거 · 감독 설계(자동 기각 · 킬스위치 · 사람 승인 지점) |
| B | 데이터 계획(D1~D7) · 첫 분기 `macro.md` · `cma.json` |
| C | 배분안 구성 계획 — 어떤 계열의 안 4개 이상, 적대적 분산자의 목적함수 |
| D | 투표 규칙 · 정량 점수 $M$의 구성 · $\lambda$ — 사전 등록표의 핵심 |
| E | MVP v0 — 우리 IPS로 첫 분기 완주, 팀원 전원 컴퓨터에서 실행 확인 |
| F (또는 전원) | 회사 소개 1쪽 · 프로포절 덱 · 창의 포인트와 성공 기준 |

## 3. 1단계에서 할 일 — 여섯 과제

### 3.1 고객 기금과 회사를 정한다 (F · 전원)

우리 회사는 **누구의 돈**을 **무엇을 위해** 운용하는가? 기본 가상 기금 KFP를 그대로 쓰지 말고 목적이 분명한 기금을 고른다. 목적이 바뀌면 IPS가 바뀌고, IPS가 바뀌면 에이전트 구성과 판정 규칙이 바뀐다 — 이것이 2단계 창의성 점수의 출발점이다.

| 고객 기금의 예 | IPS에서 달라지는 것 | 다시 볼 강의 |
|---|---|---|
| DB형 연기금 | 부채 듀레이션 대비 헤지, 적립률 하한 | W06 LDI |
| 퇴직연금 디폴트옵션 | 가입자 연령별 글라이드패스, 손실 회피 | W06 GBI · W07 동적 배분 |
| 대학 발전기금 | 지출 규칙(예: 직전 3년 평균의 5%), 실질 원금 보전, 유동성 | W14 대체투자 |
| 국부펀드 | 초장기 시계, 통화 노출 | W13 통화 헤지 |
| 보험사 일반계정 | 자본 규제, 듀레이션 매칭, 신용등급 제약 | W11 채권 |

**결과물:** 회사 소개 1쪽(`company_onepager.md`) — 회사 이름, 고객 기금, 운용 목적 한 문장, 회사가 고객에게 주는 것, 사람이 맡는 일.

### 3.2 IPS 초안을 쓴다 (A)

`ips.md` 본문과 함께 기계가 읽는 **제약 표(YAML)**를 둔다. 최소 항목은 목표 수익률, 변동성 상한, 최대낙폭 한도, 자산군 범위, 종목 상한, 분산 요건(유효 종목 수 하한)이다.

$$
N_{\text{eff}} \;=\; \frac{1}{\sum_i w_i^{2}}
$$

검산: $w=(0.4,\,0.3,\,0.2,\,0.1)$이면 $N_{\text{eff}} = 1/0.30 = 3.33$이다. 하한이 4.0이면 이 안은 표결에 오르지 못한다.

**숫자마다 근거를 한 줄씩** 쓴다 — "왜 변동성 상한이 10%인가", "왜 $N_{\text{eff}}$ 하한이 4.0인가". 근거 없는 숫자는 2단계 정책 실험에서 방어할 수 없다.

### 3.3 시스템 설계도를 그린다 (전원 · A~E)

한 장짜리 구조도 — 에이전트 · 스킬 · 하네스 · 데이터 흐름 · 사람 결정 지점. 그리고 **예시 MVP와 무엇이 달라지는지** 표를 만든다.

| 부분 | 예시 MVP | 우리 회사 (계획) | 바꾸는 이유 |
|---|---|---|---|
| 고객 기금 · IPS | KFP | (§3.1의 기금) | |
| 판단 부분 | 규칙 기반 대역 | 리서치 메모 · 검토 의견 · 투표 순위 · IC 보고서 중 최소 셋을 LLM 에이전트로 | |
| 배분안 | 6개 | (팀 구성) | |
| 창의 기능 | — | (§3.5의 창의 포인트) | |

### 3.4 데이터 계획을 세운다 (B)

| # | 데이터 | 최소 요건 |
|---|---|---|
| D1 | 투자 유니버스의 총수익률(월간) | 자산 8개 이상, 학습 84개월 + 평가 구간, 배당·이자 포함 |
| D2 | 무위험 수익률 | 기금 통화 기준 단기 금리 |
| D3 | 비교 기준(정책 벤치마크) | 기금 목적에 맞는 것 — 60/40이 기본은 아니다 |
| D4 | 국면 판정용 매크로 지표 | 3개 이상, 지표별 **발표 지연** 명시 |
| D5 | 기금 고유 데이터 | 부채·지출·납입·현금흐름 중 기금에 맞는 것 |
| D6 | 리서치 자료 목록 | 제목 · **공개일** · 출처 · 링크 |
| D7 | 사람의 결정 | `cio_decisions.csv`, `approvals.csv` |

각 데이터의 출처 · 기간 · 발표 지연을 표로 낸다. **시점 잠금(as_of)** — 분기 말의 결정에는 그때 실제로 알 수 있었던 값만 쓴다.

### 3.5 사전 등록표를 쓴다 (D · 전원)

`PREREG.md` — **결과를 보기 전에** 정하는 값들이다. 나중에 바꾸면 사유를 `CHANGELOG.md`에 남긴다.

- 투표 규칙과 득표·정량 점수의 결합 비중 $\lambda$:
$$
\text{Score}_i=\lambda\,\hat S_i+(1-\lambda)\,M_i
$$
- 정량 점수 $M$의 구성(백테스트 샤프 · IPS 여유 · 분산도 · 국면 적합 · 추정 위험 등)
- 기대수익률 수축 강도 $\delta$, 평가 지표, 비교 기준
- **창의 포인트 1개 이상과 그 성공 기준** — "무엇이 어떻게 되면 성공인가"를 숫자로

### 3.6 MVP v0 — 시연 화면으로 첫 분기를 돌린다 (E · 전원)

1. 예시 MVP를 팀 저장소로 복사하고 `ips.md`를 우리 IPS로 바꾼다.
2. `start.command`(맥) · `start.bat`(윈도)를 더블클릭해 **시연 화면**을 연다.
3. 첫 분기(2022-08)를 고르고 **▶ 라이브 실행** → 엔진이 IC 보고서까지 계산하고 **⑨ 사람 CIO 결정**에서 멈춘다.
4. 팀의 CIO가 IC 보고서를 읽고 ✓ 승인 또는 ✕ 반려, 사유를 적는다 → **1쪽 보고서**가 나온다. 보고서에 나온 행을 `data/cio_decisions.csv`에 적는다.
5. 팀원 전원 컴퓨터에서 같은 숫자가 나오는지 확인한다.

판단 부분은 예시의 대역 그대로여도 된다. `runs/2022-08/`에 산출물이 있고 README대로 다른 사람이 다시 돌릴 수 있으면 **통과**다.

**권장 — 입력 하나 바꿔 보기.** 시연 화면의 📥 입력 파일 칸에 IPS 조항 하나를 바꾼 파일을 올려 다시 돌려 본다. 표준 형식 md로 써도 되고, 회의 메모 같은 자유 형식으로 써도 된다 — 자유 형식이면 접수 에이전트가 표준 형식으로 옮겨 보여 주고 사람이 확인한 뒤 들어간다. 쓰는 법: `3_Example_MVP/올릴파일/README.md`.

## 6. 평가와 피드백

1단계는 **점수를 매기지 않는다.** 교수는 아래 기준마다 「통과」 또는 「보완」을 표시해 돌려준다. 「보완」 항목은 2단계 첫 주(W10)까지 고치고, 2단계 최종 보고서 첫 장에 **피드백 반영표**(지적 · 고친 내용 · 파일)를 둔다.

| 기준 | 통과의 모습 |
|---|---|
| 고객과 목적 | 기금의 목적이 IPS 숫자로 이어진다 |
| IPS | 제약 표가 기계로 읽히고, 숫자마다 근거가 있다 |
| 설계도 | 사람 결정 지점 · 자동 기각 · 감사 기록이 그림에 보인다 |
| 데이터 | D1~D7의 출처와 발표 지연이 적혀 있다 |
| 사전 등록 | $\lambda$ · $M$ · $\delta$ · 창의 성공 기준이 숫자로 정해져 있다 |
| MVP v0 | 시연 화면에서 첫 분기가 사람 CIO 결정까지 돈다 |

**감점(2단계 점수에서).** MVP v0 미제출 −5. 사전 등록값을 기록 없이 바꾼 경우 −5.
