## 팀원 여섯 명의 역할

팀원은 회사의 부서를 하나씩 맡는 매니저입니다. 5명 팀은 대외·기획 매니저 일을 팀 전원이 나눠 맡습니다. 자세한 내용은 1단계 가이드 2쪽 ‘팀’에 있습니다.

| 매니저 | 회사에서는 | 프로포절에서 낼 것 |
| --- | --- | --- |
| 거버넌스 매니저 | 이사회 · 준법 | IPS 초안(숫자마다 근거), 감독 설계(자동 기각 · 킬스위치 · 사람 승인 지점) |
| 리서치 매니저 | 리서치 부서 | 데이터 계획, 첫 분기의 국면 판정과 자본시장가정(CMA) |
| 포트폴리오 매니저 | 운용 부서 | 배분안 구성 계획 — 서로 다른 안 4개 이상 |
| 리스크·심의 매니저 | 리스크 · 투자위원회 | 투표 규칙과 사전 등록표의 핵심 |
| 운영 플랫폼 매니저 | 운영 · IT | MVP 초안(v0) — 우리 IPS로 첫 분기 완주, 팀원 전원 컴퓨터에서 실행 확인, 발표에서 시연 |
| 대외·기획 매니저 | 고객 · 기획 | 회사 소개 1쪽, 프로포절 덱, 창의 아이디어와 성공 기준 |

CIO(최종 결정자)는 팀원 한 명이 겸하되, 거버넌스 매니저는 겸하지 않습니다.

## MVP 초안 — 프로포절에서 직접 보여 준다

프로포절은 설계도만 내는 자리가 아닙니다. 우리 팀의 **MVP 초안(MVP v0)**을 내고, 발표 중 2분 동안 시연 화면으로 직접 돌려 보입니다. 자세한 절차는 1단계 가이드 4쪽 ‘MVP 초안(v0) — 시연 화면으로 첫 분기를 돌린다’에 있습니다.

| 구분 | MVP 초안에 담을 것 |
| --- | --- |
| **반드시** | 예시 MVP를 우리 팀 저장소로 가져와 `ips.md`를 우리 IPS로 바꾼다 |
| **반드시** | 시연 화면에서 첫 분기(2022-08)를 끝까지 돌린다 — IC 보고서 → 우리 CIO의 승인·반려와 사유 → 1쪽 보고서 |
| **반드시** | 팀원 전원의 컴퓨터에서 같은 숫자가 나온다 |
| 권장 | 입력 하나를 바꿔 다시 돌려 본다 — IPS 조항 하나를 바꾼 파일을 시연 화면에 올린다([올릴파일 예시](https://github.com/keerhee/pension-fund-strategy-and-performance/blob/main/Final_Project/1_Student/3_Example_MVP/%EC%98%AC%EB%A6%B4%ED%8C%8C%EC%9D%BC/README.md)) |
| 권장 | 예시와 달라지는 우리 팀의 첫 부품 하나 — 우리 기금에만 있는 데이터 한 가지, 또는 우리가 더한 배분안 하나 |

**발표에서 보여 주는 순서 (2분)** — 운영 플랫폼 매니저가 화면을 돌리고, CIO가 결정을 말합니다.

1. 시연 화면에서 첫 분기를 고르고 ▶ 라이브 실행
2. IC 보고서가 나오면 CIO가 승인 또는 반려하고, 그 이유를 한 문장으로 말한다
3. 1쪽 보고서를 띄운다
4. (권장을 했다면) 입력 하나를 바꾼 결과와 ‘두 실행 비교’를 보여 준다

판단 부분은 예시의 규칙 기반 대역을 그대로 써도 됩니다. LLM 에이전트로 바꾸는 일은 발표 뒤 2단계에서 합니다. 발표 당일 화면이 뜨지 않는 사고에 대비해, 한 번 돌린 화면을 녹화해 두는 것을 권합니다.

## 예시 MVP 내려받아 돌리기

저장소 전체는 약 570MB라, 학생 폴더만 받는 편이 빠릅니다. 수업에서 나눔 `XS_Example_MVP.zip`이 있다면 그것을 풀어 3번부터 해도 됩니다.

1. 학생 폴더만 내려받습니다(git 필요).

```bash
git clone --filter=blob:none --sparse https://github.com/keerhee/pension-fund-strategy-and-performance.git
cd pension-fund-strategy-and-performance
git sparse-checkout set Final_Project/1_Student
```

2. `Final_Project/1_Student/3_Example_MVP` 폴더를 팀 저장소로 복사합니다. 이 폴더를 고쳐 우리 팀의 MVP v0를 만듭니다.
3. `start.command`(맥) 또는 `start.bat`(윈도)를 더블클릭합니다. 파이썬 3.10 이상이 필요하고, 처음 한 번은 패키지 설치에 1~2분 걸립니다.
4. 브라우저에 시연 화면(localhost:8765)이 열리면 ▷ 제출본 재생과 ▶ 라이브 실행을 한 번씩 눌러 봅니다. 사람 CIO 승인 단계에서 멈추는 것이 정상입니다.
5. 우리 IPS로 바꾼 뒤 첫 분기(2022-08)를 끝까지 돌리면 MVP v0입니다. Claude Code에게 시킬 문장은 과제문 15쪽 ‘시작 키트’에 있습니다.

더 자세한 사용법은 예시 MVP의 [README.md](https://github.com/keerhee/pension-fund-strategy-and-performance/blob/main/Final_Project/1_Student/3_Example_MVP/README.md)에 있습니다. 파이썬이 없으면 `dashboard.html`을 브라우저로 열어 읽기 전용으로 봅니다.

## 프로포절 제출 전 점검

발표 전날까지 덱 · 사전 등록표 · MVP v0 저장소를 냅니다. 내기 전에 아래를 확인하세요. 전체 목록은 1단계 가이드 5쪽 ‘제출물’과 6쪽 ‘제출 전 점검표’에 있습니다.

- [ ] IPS의 숫자마다 근거가 적혀 있는가
- [ ] 시스템 설계도에 사람(CIO)이 결정하는 지점이 보이는가
- [ ] 데이터 계획에 출처 · 기간 · 발표 지연이 있는가
- [ ] 사전 등록표(`PREREG.md`)에 투표 규칙과 평가 지표가 지금 정해져 있는가 — ‘나중에 정하겠다’는 안 됩니다
- [ ] MVP v0가 우리 IPS로 첫 분기를 끝까지 돌고, `runs/2022-08`에 IC 보고서 · CIO 결정 · 감사 기록이 남는가
- [ ] 팀원 전원의 컴퓨터에서 `start` 파일 더블클릭만으로 시연 화면이 뜨는가
- [ ] 덱이 10장 이내이고 발표 10분에 맞는가
